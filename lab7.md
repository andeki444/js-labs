# Лабораторная работа №7 - Киселёв Денис Александрович

## Цель
Изучить влияние различных способов добавления и удаления узлов DOM на производительность клиентских веб-приложений.

## Методика
- Для добавления элементов тестировались методы: `appendChild`, `DocumentFragment`, `innerHTML`, `insertAdjacentHTML`.
- Для очистки контейнера тестировались методы: `innerHTML = ''`, цикл с `removeChild`, `replaceChildren()`.
- Для каждого метода проводилось 30 итераций.
- Количество элементов: 1 000 и 10 000.
- Прогрев выполнялся перед основными замерами.
- Использовался `performance.now()` для измерения времени.
- Рассчитаны среднее, стандартное отклонение и 95% доверительный интервал.

## Выводы
1. **Добавление элементов**
   - Для 1 000 элементов самым быстрым оказался `innerHTML` (0.653 мс), а медленнее всех `insertAdjacentHTML` (2.210 мс).
   - Для 10 000 элементов самым быстрым был `innerHTML` (7.883 мс) и `DocumentFragment` (10.760 мс), медленнее всего `insertAdjacentHTML` (21.993 мс), вероятно из-за многократной вставки строк в DOM.
   - Использование `DocumentFragment` эффективно для больших выборок, так как минимизирует перерасчёт компоновки.

2. **Удаление элементов**
   - Для обоих размеров контейнера самым быстрым способом очистки оказался `innerHTML = ''`.
   - Цикл с `removeChild` медленнее, особенно при большом количестве элементов.
   - `replaceChildren()` находится между ними по производительности и обеспечивает чистый код без создания лишнего HTML.

3. **Статистическая значимость**
   - CI 95% для `innerHTML` и `DocumentFragment` практически не пересекаются с CI `insertAdjacentHTML`, что подтверждает статистически значимое различие между методами.
   - Для очистки разница между методами также статистически значима при пересечении доверительных интервалов.

4. **Выбор оптимального метода**
   - Для массового добавления элементов: `DocumentFragment` или `innerHTML`.
   - Для очистки контейнера: `innerHTML = ''` или `replaceChildren()`.
   - Использование `appendChild` для больших объемов элементов менее эффективно из-за повторных перерасчётов DOM.
