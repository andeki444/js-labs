# Лабораторная работа №8

## Цель работы

Изучить основные причины утечек памяти в веб-приложениях при работе с DOM-деревом, обработчиками событий и замыканиями. Научиться использовать вкладку Memory в DevTools для обнаружения утечек памяти и анализа причин удержания объектов сборщиком мусора.

---

# Сценарий №1. Забытые обработчики событий

## Описание сценария

При создании карточек для каждой из них регистрировался обработчик события на объекте `window`. После удаления карточек из DOM обработчики событий намеренно не удалялись.

Из-за этого глобальный объект `window` продолжал хранить ссылки на удалённые элементы через функции-обработчики.

---

## Последовательность действий

1. Открыта вкладка Memory в DevTools.
2. Выполнен первый Heap Snapshot.
3. Созданы карточки кнопкой «Запустить».
4. Карточки удалены кнопкой «Очистить».
5. Выполнен принудительный вызов Garbage Collector.
6. Выполнен второй Heap Snapshot.
7. Процедура повторена ещё раз.
8. Выполнен третий Heap Snapshot.

## Причина утечки

После удаления карточек из DOM обработчики событий остались зарегистрированы на объекте `window`.

Существует цепочка ссылок:

window → EventListener → callback → DOM-элемент

Пока существует обработчик события, сборщик мусора не может удалить карточку из памяти.

---

## Способ устранения

При удалении элементов необходимо вызывать:

```javascript
window.removeEventListener(...)
```

# Сценарий №2. Сохранение DOM-узлов в глобальной структуре

## Описание сценария

Создан глобальный массив для кэширования DOM-элементов.

После удаления карточек из DOM ссылки на них оставались внутри массива.

---

## Последовательность действий

1. Выполнен Heap Snapshot.
2. Созданы карточки.
3. Карточки удалены из DOM.
4. Выполнен Garbage Collection.
5. Выполнены второй и третий снимки памяти.

## Причина утечки

Удалённые элементы продолжали храниться в глобальном массиве.

Цепочка ссылок:

window → globalCache → DOM-элемент

Несмотря на удаление элемента из DOM-дерева, ссылка в массиве не позволяла сборщику мусора освободить память.

---

## Способ устранения

После удаления элементов необходимо очищать кэш:

```javascript
globalCache.length = 0;
```

или

```javascript
globalCache = [];
```

# Сценарий №3. Утечка через замыкания (Closure)

## Описание сценария

Для созданных элементов запускались таймеры через `setInterval`.

После удаления элементов из DOM таймеры продолжали работать.

---

## Последовательность действий

1. Выполнен первый Heap Snapshot.
2. Созданы карточки.
3. Запущены таймеры.
4. Карточки удалены.
5. Выполнен Garbage Collection.
6. Созданы второй и третий Heap Snapshot.

## Причина утечки

Функция внутри `setInterval()` использовала DOM-элемент из внешней области видимости.

Таймер удерживал замыкание, а замыкание удерживало ссылку на DOM-элемент.

Цепочка ссылок:

window → setInterval → closure → DOM-элемент

Из-за этого Garbage Collector не мог удалить объект из памяти.

---

## Способ устранения

Перед удалением элементов необходимо останавливать таймеры:

```javascript
clearInterval(intervalId);
```

# Общий вывод

В ходе работы были исследованы три типичных причины утечек памяти в веб-приложениях:

1. Забытые обработчики событий.
2. Сохранение DOM-узлов в глобальных структурах данных.
3. Замыкания, удерживаемые таймерами.

Во всех случаях удаление элемента из DOM не приводило к освобождению памяти, поскольку на объект продолжали существовать активные ссылки.

Использование Heap Snapshot, поиска Detached DOM Nodes и анализа Retainers позволило определить источник удержания объектов в памяти и подтвердить наличие утечек.

Для предотвращения подобных проблем необходимо своевременно удалять обработчики событий, очищать глобальные структуры данных и останавливать таймеры при удалении элементов интерфейса.
